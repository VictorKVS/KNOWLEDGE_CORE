Зачем нужен зоопарк

Одна модель хорошо пишет связный ответ, но может уверенно пропустить альтернативу или повторить собственную ошибку. Несколько моделей полезны, если им назначены разные роли и если решение оценивается по evidence, а не по голосованию.

Принцип уже совместим с существующим OSINT model-stage registry: champion/challenger, independent judge, fail-closed unsupported claims и телеметрия human reject/rework.

Роли совета

Champion

Готовит сильнейший вариант решения: rationale, evidence, assumptions, unknowns, trade-offs, failure modes.

Architecture Skeptic

Ищет более простые варианты, hidden coupling, reversibility issues и преждевременный technology lock-in.

Security / Privacy Challenger

Ищет trust-boundary, data leakage, privilege, agent/tool и external-provider risks.

Operations / Reliability Challenger

Проверяет failure/recovery, SLO, support, observability, operational burden.

Cost / Delivery Challenger

Проверяет TCO, staffing, estimate assumptions, procurement, migration/rework cost.

Evidence Verifier

Проверяет, что ссылки существуют, поддерживают утверждения и не устарели. По возможности deterministic-first.

Independent Judge

Собирает consensus/dissent, показывает чего не хватает, но не придумывает консенсус.

Decision Owner

Выбирает APPROVE / CONDITIONS / MORE EVIDENCE / REWORK / REJECT / DEFER. Модели не забирают его полномочия.

Не весь зоопарк на каждую задачу

LOW — Routine document review
1 champion + schema/deterministic checks. Без совета моделей.
MEDIUM — Material engineering decision
1 champion + 2 blind challengers + evidence verifier + independent judge + human approval.
HIGH — Architecture / CTO Challenge
1 champion + 4 challengers: architecture, security, operations, cost + verifier + judge + decision owner.
CRITICAL — Security / Legal
Расширенный совет моделей только как advisory layer. Final Legal/Privacy/Residual Risk decision моделям запрещён.

Почему первый раунд слепой

Challengers не должны сначала видеть выводы друг друга. Иначе модели быстро сходятся к формальному консенсусу. Первый pass создаётся независимо; второй round допускается только для материальных расхождений.

Original task + frozen evidence snapshot ├─ Champion independently ├─ Challenger A independently ├─ Challenger B independently ├─ Challenger C independently └─ Challenger D independently ↓ Evidence verification ↓ Material disagreement? ├─ no → Judge └─ yes → cross-examination → Judge ↓ Dissent Register + Suggested Gate ↓ Human Decision

Решение не считается голосованием

Неправильно

4 модели сказали “A”, 2 модели сказали “B” → A победил.

Правильно

У A сильнее evidence по cost, но B единственный выявил Critical privacy blocker → решение BLOCKED до закрытия privacy вопроса.

Evidence strength > model vote count.

Выход — Decision Packet

Decision Packet ├─ task / document / version ├─ materiality + selected panel profile ├─ frozen input refs ├─ champion model/version ├─ challenger models/versions ├─ judge model/version ├─ options considered ├─ evidence coverage ├─ unsupported claims ├─ consensus state ├─ dissent register ├─ UNKNOWN / insufficient evidence ├─ trade-offs ├─ suggested gate outcome ├─ required human authority └─ final human decision + rationale

Зоопарк сам обучается на качестве решений

После human review сохраняем, какие предложения были приняты/отклонены. Поэтому модель назначается не потому, что она “любимая”, а потому что на конкретной capability показывает хорошую историю.

per model / per capability: - human acceptance rate - useful challenger finding rate - false challenge rate - judge agreement with human - unsupported claim count - rework rate - duration / token-compute cost - cost per accepted decision

Со временем champion/challenger для Requirements может быть одним набором, для Security — другим, для архитектуры — третьим.

Hard blocks

Нет human decision owner; source failure по материальному утверждению; sensitive data ушли в неразрешённую внешнюю модель; Legal/Residual Risk финализированы только моделями; judge спрятал dissent; champion и judge не независимы там, где независимость обязательна.
