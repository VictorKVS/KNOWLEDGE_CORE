# Learning Core

This layer turns engineering knowledge into a reusable curriculum for both humans and agents.

It is organized around **tasks, strategies, anti-patterns, elegant solutions and production transformations** rather than around isolated theory chapters.

## Learning object

Each learning object should connect:

`Problem → Junior View → Middle View → Senior View → Elegant Solution → Production Solution → Evidence → Tests → Security → Reusable Lesson`

## Content families

- typical engineering tasks;
- olympiad-derived problem solving;
- modern programming patterns;
- anti-patterns and failure modes;
- refactoring exercises;
- API and module design;
- concurrency exercises;
- reliability and production exercises;
- security-oriented coding exercises;
- cross-language implementations in Python, Go and C++.

## Difficulty model

Difficulty is not only algorithmic complexity. A task may be easy algorithmically but senior-level operationally.

Dimensions include:
- algorithmic reasoning;
- implementation complexity;
- architecture scope;
- concurrency;
- security;
- reliability;
- observability;
- performance;
- ambiguity;
- evidence required.

## Site-ready principle

Every structured learning object should be renderable later as a web page without rewriting its core content.

A future page may expose tabs such as:

- Problem
- Junior
- Middle
- Senior
- Elegant
- Production
- Python
- Go
- C++
- Tests
- Evidence
- Security
- Alternatives

The repository remains the source of truth; the site is a rendered view.
