# Translator Agent — входной слой перед аналитикой

## Назначение

Translator Agent — обязательный входной слой для англоязычных книг, статей, стандартов, документации и иных материалов до их передачи рабочим аналитикам и Главному аналитику.

## Базовый конвейер

`ORIGINAL_EN -> TEXT_EXTRACTION -> STRUCTURE -> GLOSSARY -> EN_RU_TRANSLATION -> ALIGNMENT_QA -> ANALYST_WORKERS -> CHIEF_ANALYST -> KNOWLEDGE_CORE`

Переводчик не заменяет аналитика и не делает юридические/технические выводы. Его задача — создать максимально точный русскоязычный слой, сохранив связь с оригиналом.

## Обязательные правила перевода

1. Оригинальный текст сохраняется неизменяемым.
2. Перевод хранится отдельно от оригинала.
3. Для каждого переведённого фрагмента сохраняется точный якорь: книга/документ, издание, глава, раздел, страница или иной устойчивый locator.
4. Термины не переводятся каждый раз заново: используется единый двуязычный glossary EN<->RU.
5. Неопределённые, многозначные и отраслевые термины помечаются `TERM_REVIEW_REQUIRED`.
6. Нельзя превращать перевод в пересказ, сокращение или интерпретацию.
7. Код, формулы, идентификаторы, стандартизованные имена, API, URI, номера требований и ссылки сохраняются без смысловой подмены.
8. Цитаты, определения, SHALL/MUST/SHOULD/MAY и иная модальность должны сохранять силу оригинала.
9. Переводчик не исправляет фактические ошибки автора молча; потенциальная ошибка отмечается отдельно.
10. Для ключевых фрагментов выполняется обратная проверка: RU -> EN смысловое сравнение либо независимый reviewer-проход второй моделью.

## Выходные сущности

Для каждого сегмента:

- `source_id`
- `source_sha256`
- `source_language`
- `target_language`
- `source_anchor`
- `original_text`
- `translated_text`
- `terminology_used`
- `translation_notes`
- `ambiguities`
- `confidence`
- `review_status`
- `translator_model`
- `reviewer_model`

## Роли моделей

Рекомендуемая схема для локального зоопарка:

- Primary Translator: Qwen2.5-14B-Instruct
- Translation Reviewer: GigaChat 20B A3B
- Structured-output / glossary validator: Qwen2.5-Coder-14B или DeepSeek-Coder-V2-Lite
- Embedding/alignment search: bge-m3

Роли должны выбираться по результатам A/B тестов, а не по названию модели.

## Режим книг

Книга обрабатывается не одним промптом, а по устойчивой структуре:

`BOOK -> METADATA -> TOC -> CHAPTER -> SECTION -> SEGMENT -> TRANSLATION -> QA -> KNOWLEDGE EXTRACTION`

Хранятся как минимум три слоя:

1. `ORIGINAL` — исходный файл и извлечённый оригинальный текст.
2. `TRANSLATION` — выровненный перевод EN->RU.
3. `KNOWLEDGE` — уже отдельная аналитическая выжимка: concepts, definitions, patterns, anti-patterns, decision rules, trade-offs, checklists, metrics, examples, contradictions.

Нельзя использовать перевод как замену оригинала при спорном толковании — аналитик обязан иметь возможность вернуться к исходному английскому фрагменту.

## Параллельность

Переводчик может работать перед четырьмя аналитическими потоками как отдельный feeder:

`EN SOURCE QUEUE -> TRANSLATOR -> QA -> READY_RU_QUEUE -> 4 ANALYST WORKERS -> CHIEF ANALYST`

Для больших книг допустимы 4 переводческих worker-а по главам/разделам, но glossary и терминологическая память должны быть общими.

## Acceptance gates

Материал получает статус `TRANSLATION_READY` только если:

- исходный SHA-256 сохранён;
- структура источника сохранена;
- каждый перевод имеет source anchor;
- glossary применён;
- критические термины проверены;
- нет потери модальности MUST/SHALL/SHOULD/MAY;
- reviewer не обнаружил существенной смысловой подмены;
- оригинал доступен для трассировки.

После этого материал допускается в аналитические очереди KNOWLEDGE_CORE.
