## Import rules reinforced by this pass

1. Never parse legal identity from repository filename/path alone.
2. Treat `saved edition`/`быстрый просмотр` dates in derived notes as untrusted metadata unless they can exist chronologically and are tied to a real revision.
3. A GitHub PDF is only `FULL_TEXT_VERIFIED` after internal number/date/title inspection; path + companion Markdown is sufficient only for a strong candidate.
4. Preserve independent `document_date`, `official_publication_date`, `effective_from`, `superseded_from`, and `source_snapshot_date` fields.
5. Filename/path conflicts are repo-quality issues, not legal-version edges.
