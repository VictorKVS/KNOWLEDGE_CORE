## Premium conversion sequence

```text
INVENTORY
  -> CLUSTER
  -> ROLE (flagship / component / demo / learning / archive-candidate)
  -> CONTENT REVIEW
  -> MVP CONTRACT
  -> PREMIUM README + ARCHITECTURE
  -> TESTS + CI + SECURITY
  -> DEMO
  -> RELEASE
  -> PROFILE SHOWCASE
```

### Portfolio rule

Do not make every repository equally prominent. Premium presentation requires hierarchy:

1. **Flagship** — working, polished, demoable products.
2. **Platform component** — reusable infrastructure supporting flagships.
3. **Demo / experiment** — bounded proof of a capability.
4. **Learning archive** — curated evidence of study and progression.
5. **Archive candidate** — duplicate, empty or superseded; inspect before archiving.

### Destructive-change rule

No repository is deleted, archived, renamed or merged merely because its name looks weak. First inspect content/history/dependencies and create a migration/redirect decision. This map is the navigation architecture, not permission for destructive cleanup.
